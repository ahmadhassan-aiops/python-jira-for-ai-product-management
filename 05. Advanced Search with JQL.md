# 05. Advanced Search with JQL

**JQL (Jira Query Language)** is a text language for searching issues. Every basic search is converted to JQL behind the scenes, and every filter, board and automation rule runs on it. The Python scripts later in this course search with JQL too.

Open it from **Filters > Search issues > Switch to JQL** (or the **JQL** toggle).

Documentation: https://support.atlassian.com/jira-software-cloud/docs/use-advanced-search-with-jira-query-language-jql/

## Structure of a Query

```text
field  operator  value   [AND | OR]   field  operator  value ...   [ORDER BY field ASC|DESC]
```

```sql
project = PP AND issuetype = Story AND status = "To Do"
```

- **Fields:** `project`, `issuetype`, `status`, `assignee`, `reporter`, `priority`, `created`, `resolution`, `text` and more.
- **Values with spaces** need quotes: `"To Do"`, `"Python Project"`.
- **Keywords** (`AND`, `OR`, `NOT`, `ORDER BY`) are not case-sensitive.

## Operators

| Operator | Meaning | Example |
|---|---|---|
| `=` / `!=` | Equal / not equal | `status != Done` |
| `in` / `not in` | Any of a list | `status in ("In Progress", "To Do")` |
| `>`, `>=`, `<`, `<=` | Comparison (dates, numbers) | `created >= 2022-11-01` |
| `~` | Contains text | `text ~ "user"` |
| `is EMPTY` / `is not EMPTY` | Field has no value | `assignee is EMPTY` |
| `was`, `changed` | History searches | `status was "In Progress"` |

## Status and Assignee Queries

```sql
-- stories waiting to be picked up, unassigned or assigned to me
project = PP AND issuetype = Story AND status = "To Do" AND assignee in (EMPTY, currentUser())

-- open work in two statuses
project = PP AND issuetype = Story AND status in ("In Progress", "To Do") AND assignee in (EMPTY, currentUser())

-- only unassigned (both lines mean the same)
project = PP AND issuetype = Story AND status in ("In Progress", "To Do") AND assignee in (EMPTY)
project = PP AND issuetype = Story AND status in ("In Progress", "To Do") AND assignee = EMPTY

-- finished stories (both lines mean the same)
project = PP AND issuetype = Story AND status = Done
project = PP AND issuetype = Story AND status in (Done)
```

`currentUser()` is a **function**: it means whoever runs the search, so one saved filter works for everyone.

## Writing Your Own Queries

**Requirement:** epics in the Python Project that are in progress.

```sql
project = "Python Project" AND issuetype = Epic AND status = "In Progress"
```

**Requirement:** stories that are not finished yet.

```sql
-- wrong: an issue can't be in two statuses at once, so this returns nothing
project = "Python Project" AND issuetype = Story AND status = "In Progress" AND status = "To Do"

-- right
project = "Python Project" AND issuetype = Story AND status in ("In Progress", "To Do")

-- also right, and it keeps working if someone adds a new status later
project = "Python Project" AND issuetype = Story AND status != Done
```

> **Basic vs JQL mode:** simple queries like the `status in (...)` version switch back to the basic dropdowns. Queries with `!=` or functions are too complex for the dropdowns, so Jira keeps them in JQL mode.

**Requirement:** open stories that mention "user".

```sql
project = PP AND issuetype = Story AND status in ("In Progress", "To Do") AND text ~ "user"
```

**Requirement:** everything in one epic.

```sql
parent = AC-4
```

> Older sites used `"Epic Link" = AC-4`. Jira Cloud replaced the Epic Link field with **parent**, so use `parent` on current sites.

## Date Queries

| Query | Finds |
|---|---|
| `created >= 2022-11-01 AND created <= 2022-11-30 AND project = PP AND status in ("In Progress", "To Do")` | Open issues created in November 2022 |
| `created >= 2022-11-01 AND created <= 2022-11-30 AND project = PP AND status = Done` | Done issues from that month |
| `created >= 2022-10-01 AND created <= 2022-10-31 AND project = PP` | Every issue from October 2022 |
| `project = "Python Project" AND created > startOfDay("-1")` | Issues created since the start of yesterday |
| `project = "Python Project" AND resolutiondate >= startOfMonth() AND resolutiondate <= endOfMonth()` | Issues resolved this month |
| `created >= -5m` | Created in the last 5 minutes |
| `created >= -3h` | Created in the last 3 hours (used by the email project in topic 14) |

Relative dates: `-5m` (minutes), `-3h` (hours), `-1d` (days), `-2w` (weeks).
Date functions: `startOfDay()`, `endOfDay()`, `startOfWeek()`, `startOfMonth()`, `endOfMonth()`, `startOfYear()`, each optionally with an offset like `startOfMonth("-1")` for last month.

## Sorting

```sql
project = IIP AND priority = Highest ORDER BY created DESC
```

## Practice Tasks

Write a query for each requirement, then compare with the solution.

**Task 1.** Highest-priority issues in the IIP project created in November 2022, newest first.

```sql
project = IIP AND created >= 2022-11-01 AND created <= 2022-11-30 AND priority = Highest ORDER BY created DESC
```

**Task 2.** Issues that are past *To Do* but still have no description.

```sql
status != "To Do" AND description is EMPTY
```

**Task 3.** Unassigned issues older than one day (nobody has picked them up).

```sql
assignee is EMPTY AND created < -1d
```

**Task 4.** Unresolved tasks in MYP created in the last 3 hours with no assignee.

```sql
project = MYP AND issuetype = Task AND created >= -3h AND assignee is EMPTY AND resolution = Unresolved
```

> Save useful queries as **filters** (**Save as**), then subscribe to them: Jira emails you the results on a schedule.
